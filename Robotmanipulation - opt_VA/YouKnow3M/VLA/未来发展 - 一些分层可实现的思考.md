这个问题非常实在，我把它做成一个**可执行的工程评估**——按"移植成本 × 收益"打分排序，给你最具体的落地建议。

## 一、先把当前 VLA 的"视觉瓶颈"看清楚

```text
GR00T:  RGB → SigLIP/Eagle-2 → 2D patch tokens → cross-attn → DiT
π0.5:   RGB → SigLIP → 2D patch tokens → joint attn → Gemma Expert
```

**问题**：这两个 backbone 都是为"语义识别"训练的（ImageNet/COCO/web image），不是为"几何感知 + 物理建模"训练的。它们不知道：
- 物体的 3D 位姿
- 物体之间的相对距离
- 运动的因果关系
- 视角变换下的等变性

要补的就是这些东西。

## 三、最值得"立刻就动手"的 5 个移植方案（按 ROI 排序）

### ⭐ 第 1 名：**DINOv2/v3 替换 SigLIP 作为 Vision Encoder**

**移植成本**：极低（一周内可完成）  
**预期收益**：极高（OOD 鲁棒性、空间感知大幅提升）

具体改动（以 π0.5 为例）：

```python
# 当前 π0.5 用的是 PaliGemma 自带的 SigLIP
self.paligemma = PaliGemmaForConditionalGeneration(config=vlm_config_hf)
# embed_image 调用的是 paligemma 内部的 SigLIP vision tower

# 改造：把 vision tower 换成 DINOv2，加一个对齐 projection
self.dino = torch.hub.load('facebookresearch/dinov2', 'dinov2_vitl14')
self.dino_proj = nn.Linear(1024, vlm_config.width)  # DINOv2-L → PaliGemma hidden_size
```

**为什么 DINOv2 是首选**：
- **自监督训练**：不依赖 ImageNet 标签，learns 更通用的视觉结构
- **空间感知强**：dense feature map 自带空间结构信息（在 patch 间有很强的对应关系）
- **OOD 强**：在没见过的场景、物体上依然 work
- **已被 robotics 验证**：DROID 数据集、OpenVLA、Octo、HumanPlus 等都验证过

**有论文已经证明**：[Theia 论文](https://arxiv.org/abs/2407.20179)系统对比过 robotics 任务上各 vision encoder，**DINOv2 > SigLIP > CLIP**。

### ⭐ 第 2 名：**DepthAnything V2 作为辅助深度分支**

**移植成本**：低（两周）  
**预期收益**：高（直接解决"语言无法精确描述空间"问题）

```python
# 加一个 depth encoder branch
from depth_anything_v2 import DepthAnythingV2
self.depth_model = DepthAnythingV2.from_pretrained("depth-anything/Depth-Anything-V2-Large")
self.depth_proj = nn.Linear(depth_feature_dim, vlm_config.width)

# 在 embed_prefix 里增加 depth tokens
def embed_prefix(self, images, ...):
    img_emb = self.paligemma_with_expert.embed_image(images)
    
    with torch.no_grad():
        depth_map = self.depth_model(images)
    depth_emb = self.depth_encoder(depth_map)
    depth_emb = self.depth_proj(depth_emb)
    
    embs = torch.cat([img_emb, depth_emb], dim=1)  # 拼接，让 LLM 同时看 RGB 和 depth
    ...
```

**为什么 DepthAnything V2 这么香**：
- **零 fine-tune**：直接 monocular 单图就能出深度（已经在 62M 图像上预训练）
- **精度足够**：相对深度精度足以支撑大部分操作任务
- **推理快**：ViT-L 版本 30FPS 在 A100 上
- **跟现有 RGB pipeline 无缝**：不需要 RGB-D 相机

**直接的收益**：模型能"看出来"杯子在桌子前 30cm 还是后 30cm —— 这是当前 VLA 完全做不到的。

### ⭐ 第 3 名：**Theia（NVIDIA Robotics 出品）一站式 visual encoder**

**移植成本**：极低（两三天）  
**预期收益**：中高（多模态视觉信号一次性到位）

[Theia](https://github.com/bdaiinstitute/theia) 是把 **DINOv2 + SAM + Depth-Anything + CLIP + ViT-MAE** 五个模型**蒸馏到一个 ViT** 里——一次前向传播，同时拿到：
- DINOv2 的语义/空间特征
- SAM 的分割能力
- Depth-Anything 的深度信息
- CLIP 的语言对齐

```python
from theia import TheiaModel
self.vision = TheiaModel.from_pretrained("theia-base-patch16-224-cdiv")
```

**为什么推荐**：
- 已经为 robotics 优化（论文里直接对比了 manipulation 任务）
- 蒸馏后比单独跑五个模型快 10 倍
- **它就是为了替换 SigLIP 这种"通用视觉 backbone" 设计的**

### ⭐ 第 4 名：**SAM2 + RoboFlamingo 风格 Object-Centric Tokens**

**移植成本**：中（一个月）  
**预期收益**：高（让 VLA 显式知道有哪些物体）

```python
from sam2 import SAM2ImagePredictor
self.sam2 = SAM2ImagePredictor.from_pretrained("facebook/sam2-hiera-large")

def get_object_tokens(self, image):
    masks = self.sam2.auto_segment(image)  # 自动分割所有物体
    object_features = []
    for mask in masks:
        roi_feature = roi_align(self.vision_features, mask.bbox)
        object_features.append(roi_feature)
    return torch.stack(object_features)  # (N_objects, feature_dim)
```

然后把 `object_tokens` 跟 image_tokens 一起拼进 prefix。

**收益**：
- 模型从"看一堆 patch"升级到"看一堆物体"
- 显式建模物体的存在性、空间关系
- 对 "pick up the red block" 这种 referring expression 任务直接受益

### ⭐ 第 5 名：**V-JEPA 2 作为辅助 Visual Latent（动力学先验）**

**移植成本**：中（一个月，需要少量 fine-tune）  
**预期收益**：中（动力学先验，长时序受益）

[V-JEPA 2](https://github.com/facebookresearch/jepa) 是 Meta 2025 年发布的，在 1M+ 小时视频上自监督训练。它的 latent 编码了**"事物如何运动"**这种 World Model 风格的先验。

```python
from jepa import VJEPA
self.vjepa = VJEPA.from_pretrained("facebook/vjepa-v2-l")

# 把 V-JEPA 的 latent 作为额外 token 流
vjepa_features = self.vjepa.encode(image_history)  # 多帧输入
vjepa_tokens = self.vjepa_proj(vjepa_features)
```

**核心优势**：
- 跟 DINOv2 的"静态语义"互补，提供"动态物理"信号
- 已经预训练好，开源 checkpoint 可用
- 完全不依赖 robot data

## 四、终极组合方案（如果让我设计 GR00T-N2 / π0.6）

如果我有 3 个月时间在 GR00T/π0.5 基础上做"下一代"，我会做这个组合：

```text
                                    ┌─────────────────────────┐
                                    │  Theia (DINOv2+SAM+     │
                                    │   Depth + CLIP)         │← RGB
                                    └────────┬────────────────┘
                                             │ image_tokens (语义+几何)
                                             │
                                    ┌────────▼────────────────┐
                                    │  V-JEPA 2 (frozen)      │← RGB sequence
                                    └────────┬────────────────┘
                                             │ dynamics_tokens (物理)
                                             │
RGB-D ────────────────► PointTransformer V3 ─┴──► 3D_tokens (几何/位姿)
                                             │
Language ────────────► PaliGemma tokenizer ──┴──► language_tokens (任务)
                                             │
                                             ▼
                            ┌────────────────────────────────────┐
                            │  Multi-Stream Transformer (MoT)    │
                            │  Joint Attention 跨四种 token 流    │
                            └────────────────┬───────────────────┘
                                             │
                                             ▼
                            ┌────────────────────────────────────┐
                            │  Hierarchical Action Expert        │
                            │  Subtask → Skill → Flow Matching   │
                            └────────────────────────────────────┘
```

**四路 token 互补**：
- `image_tokens`（Theia）：当前帧的语义 + 几何（替换 SigLIP）
- `3D_tokens`（PointTransformer V3）：精确的 3D 几何（如果有 RGB-D）
- `dynamics_tokens`（V-JEPA 2）：动力学预测（来自 video pretrain）
- `language_tokens`（PaliGemma tokenizer）：任务、推理、规划

**每个 token 类型用各自专属的 type embedding**，joint attention 时模型自己学着该看哪个。

## 五、最实用的"今天就动手"建议

如果你现在就要在你的 GR00T fine-tune pipeline 上做实验，按这个顺序逐步迭代：

| 阶段 | 改动 | 预期效果 | 工期 |
|------|------|----------|------|
| **Week 1-2** | 把 Eagle/SigLIP 的 vision tower 替换为 **DINOv2-L** | OOD 鲁棒性 +20~30% | 1 周代码 + 1 周训练 |
| **Week 3-4** | 加 **DepthAnything V2** 作为辅助深度 token | 精细操作任务 +10~20% | 1 周 |
| **Week 5-8** | 引入 **SAM2 object-centric tokens** | Referring/Reasoning 任务大幅提升 | 1 月 |
| **Week 9-12** | 加 **V-JEPA 2 dynamics token** | 长时序任务受益 | 1 月 |
| **Month 4+** | 升级到 **Theia + PointTransformer V3 + RGB-D** 完整方案 | 全方位提升 | 2~3 月 |

**起手最容易的就是 DINOv2 替换 SigLIP**——一周可以出 ablation 结果，给你的论文/项目立刻加分。

## 六、几个重要的"避坑提醒"

1. **不要直接上 NeRF / Per-scene 3DGS**：per-scene 优化的方法**不适合 robot 实时控制**（每次新场景要重训）。要用 feed-forward 版本（LGM、MVSplat、GS-LRM）。

2. **不要追求"all-in-one foundation model"**：当前没有任何单一模型能同时做好 3D + dynamics + semantic。多 token 流是工程上更现实的方案。

3. **不要忽视 frozen prior 的价值**：Theia / DINOv2 / V-JEPA 这种**预训练 + frozen** 的策略比 fine-tune from scratch 更稳。robot data 太少，频繁解冻预训练 backbone 会破坏先验。

4. **不要忘了 head_dim 对齐**：如果想做 joint attention（像 π0.5 那样），新加的 token branch 输出的 head_dim 最好跟 LLM backbone 对齐（PaliGemma 是 256）—— 这样能直接拼接 K/V。

## 一句话总结

> **如果只能选一个立刻移植：DINOv2 替换 SigLIP，最低成本最高收益。**
> **如果有 3 个月：Theia（DINOv2+SAM+Depth+CLIP 一体化）+ DepthAnything 辅助 + V-JEPA 2 动力学先验，三件套打底。**
> **如果做 SOTA：再加上 PointTransformer V3 处理 RGB-D point cloud，四路 token 进 Multi-Stream Transformer 做 joint attention。**

工程上**最现实的路径是先扩 vision encoder，不要先动 transformer 主架构**——backbone 一换，下游所有东西自动受益，这才是 ROI 最高的工程演化路径。


# 四个token流应该如何协作？
---
你这个问题问得非常好——我之前那个图确实有歧义，箭头让人以为是顺序依赖。让我把这个事情**从信息论、依赖关系、Attention 设计**三个层面彻底讲清楚。

## 一、依赖关系：四流其实是"完全并行独立的"

我之前的画图风格容易让人误解，先严格说明：

```text
RGB (单帧)          ─────► Theia              ─────► image_tokens
RGB sequence (N帧)  ─────► V-JEPA 2 (frozen)  ─────► dynamics_tokens
RGB-D point cloud   ─────► PointTransformer V3 ────► 3D_tokens
Language (text)     ─────► PaliGemma tokenizer ────► language_tokens
```

**关键事实**：

| 模块 | 输入 | 输出 | 是否依赖其他流 |
|------|------|------|----------------|
| Theia | 单帧 RGB | 语义+几何 token | **完全独立** |
| V-JEPA 2 | RGB 序列（多帧） | 动力学 latent | **完全独立** |
| PointTransformer V3 | RGB-D 或 LiDAR 点云 | 3D 几何 token | **完全独立** |
| PaliGemma Tokenizer | 文本 | 语言 token embedding | **完全独立** |

**为什么必须独立？**
1. **输入模态完全不同**：单帧/序列/点云/文本，物理上就是不同传感器的数据
2. **计算效率**：四个 encoder 可以**完全并行**跑在不同 GPU stream 上
3. **预训练权重独立**：四个模型来自不同的 foundation model，没有任何共享权重
4. **可热插拔**：如果哪个流性能不好，单独换掉不影响其他流

**我之前的图错在哪**：画了一条竖线箭头让看起来像 pipeline，实际应该是横向并列。

## 二、正确的并行架构图

```text
┌──────────────┬──────────────┬──────────────┬──────────────┐
│   单帧 RGB    │  RGB 序列     │   RGB-D 点云  │     文本      │
│  (B,1,3,H,W) │ (B,N,3,H,W)  │  (B,Np,6)    │  (B,Lt)      │
└──────┬───────┴──────┬───────┴──────┬───────┴──────┬───────┘
       │              │              │              │
       │ (并行计算)    │ (并行计算)    │ (并行计算)    │ (并行计算)
       ▼              ▼              ▼              ▼
┌──────────────┐┌──────────────┐┌──────────────┐┌──────────────┐
│    Theia     ││  V-JEPA 2    ││ PointTransV3 ││  PaliGemma   │
│              ││  (frozen)    ││              ││  tokenizer   │
│              ││              ││              ││              │
└──────┬───────┘└──────┬───────┘└──────┬───────┘└──────┬───────┘
       │              │              │              │
       │ d=1024       │ d=1024       │ d=512        │ d=2048
       │              │              │              │
       ▼              ▼              ▼              ▼
┌──────────────┐┌──────────────┐┌──────────────┐┌──────────────┐
│  Linear+LN   ││  Linear+LN   ││  Linear+LN   ││  (already    │
│ d→D_model    ││ d→D_model    ││ d→D_model    ││   D_model)   │
└──────┬───────┘└──────┬───────┘└──────┬───────┘└──────┬───────┘
       │              │              │              │
       │ + img type   │ + dyn type   │ + 3d type    │ + lang type
       │   embedding  │   embedding  │   embedding  │   embedding
       │              │              │              │
       ▼              ▼              ▼              ▼
   img_tokens     dyn_tokens     3d_tokens     lang_tokens
   (B,T_img,D)    (B,T_dyn,D)    (B,T_3d,D)    (B,T_lang,D)
       │              │              │              │
       └──────────────┴──────┬───────┴──────────────┘
                             │
                             │ torch.cat(dim=1)
                             ▼
                    world_tokens (B, T_total, D)
                    T_total = T_img + T_dyn + T_3d + T_lang
                             │
                             ▼
                    ┌──────────────────────┐
                    │   Multi-Stream       │
                    │   Transformer (MoT)  │ ← 跨流融合发生在这里
                    └──────────┬───────────┘
                               │
                               ▼ world_representation
                    ┌──────────────────────┐
                    │ Action Expert        │
                    │ (Gemma-style)        │ ← 这里做 action 生成
                    └──────────────────────┘
                               │
                               ▼
                             action
```

**几个关键设计点**：

1. **统一维度**：每个 encoder 输出维度不同（Theia 1024、PointV3 512、PaliGemma 2048），用 `Linear+LayerNorm` 投到统一的 `D_model`（比如 1024）。
2. **Type Embedding**：每个 token 加一个**类型 embedding** $e_{\text{type}} \in \{e_{\text{img}}, e_{\text{dyn}}, e_{\text{3d}}, e_{\text{lang}}\}$，让模型知道这个 token 来自哪个流。
3. **拼接而非合并**：保留所有 token，不做 pooling 或 averaging。
4. **跨流融合发生在 MoT 内部**，encoder 阶段保持独立。

## 三、Q/K/V 的分配：四种设计方案及取舍

这是最核心的问题。我列四种典型设计，最后给出**推荐方案**。

### 方案 A：**完全对称 Joint Self-Attention**（π0.5 同款）

所有 token（包括 action）都拼成一个大序列，做标准 self-attention：

$$
\text{tokens} = [\,T_{\text{img}}, T_{\text{dyn}}, T_{\text{3d}}, T_{\text{lang}}, T_{\text{action}}\,] \\
Q = K = V = W_{\text{type}} \cdot \text{tokens}
$$

每个 token 都既做 Q 也做 K/V，**全双向 attention**。

| 优点 | 缺点 |
|------|------|
| 简单粗暴，让模型自己学 | 计算量 $O((T_{\text{total}})^2)$ 极大 |
| 跨流学习能力强 | 不支持 KV cache（每步要重算所有 K/V） |
| 类似 GPT 风格 | 弱 prior，需要海量数据 |

### 方案 B：**Prefix-LM Joint Attention**（π0.5 实际方案）

`[world_tokens]` 作为 prefix（双向），`[action_tokens]` 作为 suffix（attend prefix + suffix）：

```text
              IMG  DYN  3D   LANG | ACT_1 ACT_2 ... ACT_T
IMG     [  1    1    1    1   | 0     0          0    ]
DYN     [  1    1    1    1   | 0     0          0    ]
3D      [  1    1    1    1   | 0     0          0    ]
LANG    [  1    1    1    1   | 0     0          0    ]
─────────────────────────────────────────────────────
ACT_1   [  1    1    1    1   | 1     1          1    ]
ACT_2   [  1    1    1    1   | 1     1          1    ]
...
ACT_T   [  1    1    1    1   | 1     1          1    ]
```

- **World 块内部**：完全双向（四流互相 attention，跨流融合在这里发生）
- **Action 块内部**：双向（动作 token 互相 attention）
- **Action → World**：可以 attend（动作"读取"world 表征）
- **World → Action**：禁止（保证 prefix KV cache）

**Q/K/V 分配**：
- World tokens：每个流用自己 type 专属的 $W^{Q}_{\text{type}}, W^{K}_{\text{type}}, W^{V}_{\text{type}}$
- Action tokens：用 Action Expert 专属的 $W^{Q}_{\text{act}}, W^{K}_{\text{act}}, W^{V}_{\text{act}}$
- Attention 计算时**所有 token 的 K/V 在 sequence 维度拼接**

数学上：

$$
\text{Attn}(\text{ACT}_i) = \text{softmax}\!\left(\frac{Q^{\text{act}}_i \cdot [K_{\text{img}}; K_{\text{dyn}}; K_{\text{3d}}; K_{\text{lang}}; K_{\text{act}}]^\top}{\sqrt{d}} + M\right) [V_{\text{img}}; V_{\text{dyn}}; V_{\text{3d}}; V_{\text{lang}}; V_{\text{act}}]
$$

| 优点 | 缺点 |
|------|------|
| 支持 prefix KV cache（推理快） | World 端单向（无法因 action 调整） |
| 四流之间能互相融合 | 仍是单向信息流（VL → action） |
| π0.5 已验证可行 | 仍然是 single attention pattern |

### 方案 C：**Hierarchical Two-Stage Attention**（GR-2 / DreamerV3 风格）

分两阶段：先让 world tokens 互相融合，再让 action 来取信息。

**Stage 1：World Fusion**（$L_1$ 层）
- 四流 token 拼一起，做标准 self-attention
- 没有 action token 参与
- 输出 `fused_world` $\in \mathbb{R}^{T_{\text{world}} \times D}$

**Stage 2：Action Cross-Attention**（$L_2$ 层）
- Action tokens 作为 Q
- `fused_world` 作为 K/V
- 内部 self-attention 让 action token 互相协调

$$
\text{Stage 1: } \tilde{T}_w = \text{Self-Attn}^{(L_1)}([\,T_{\text{img}}, T_{\text{dyn}}, T_{\text{3d}}, T_{\text{lang}}\,]) \\
\text{Stage 2: } a = \text{Cross-Attn}^{(L_2)}(Q=T_{\text{act}}, K=V=\tilde{T}_w)
$$

| 优点 | 缺点 |
|------|------|
| 计算量小（$T_{\text{world}}^2 + T_{\text{act}} \cdot T_{\text{world}}$） | 信息单向（act 不能反向影响 world） |
| 推理时 `fused_world` 可以缓存 | World 阶段完了 action 才开始 |
| 物理直觉清晰 | 类似 GR00T 的 cross-attn，可能信息瓶颈 |

### 方案 D：**Stream-Routed Attention with Type-Aware Mixture-of-Experts**（最先进，推荐）

这是我个人最看好的方案。**核心思想**：让 action token 在每一层动态决定"现在我更需要看哪个流"。

**实现方式**：

1. **每一层都做 Joint Attention（方案 B 的 prefix-LM 模式）**
2. **但是 attention 输出后，对 action token 做 Mixture-of-Experts 路由**：

```text
for each layer:
    # Step 1: 标准 joint attention（prefix-LM mask）
    fused = JointAttention([T_img, T_dyn, T_3d, T_lang, T_act])
    
    # Step 2: 对 action token 做 stream-aware routing
    router_logits = MLP(T_act)  # (B, T_act, num_streams=4)
    routing_weights = softmax(router_logits)  # 每个 action token 决定它最关注哪个流
    
    # Step 3: 让每个流给 action 提供额外的"专用通道"
    stream_specific_attn = []
    for stream in [T_img, T_dyn, T_3d, T_lang]:
        attn = CrossAttn(Q=T_act, K=V=stream)
        stream_specific_attn.append(attn)
    
    # Step 4: 加权融合
    T_act_extra = sum(routing_weights[i] * stream_specific_attn[i] for i in range(4))
    
    # Step 5: 合并两路
    T_act_new = fused[-T_act:] + T_act_extra
```

数学上：

$$
\begin{aligned}
\tilde{a}_i^{\text{joint}} &= \text{JointAttn}(a_i, \text{all tokens}) \\
\tilde{a}_i^{\text{stream-}k} &= \text{CrossAttn}(Q=a_i, K=V=T_k), \quad k \in \{\text{img, dyn, 3d, lang}\} \\
\pi_i &= \text{Softmax}(\text{MLP}(a_i)) \in \Delta^4 \\
a_i^{\text{new}} &= \tilde{a}_i^{\text{joint}} + \sum_{k=1}^{4} \pi_i^{(k)} \cdot \tilde{a}_i^{\text{stream-}k}
\end{aligned}
$$

| 优点 | 缺点 |
|------|------|
| 模型可学不同 action 阶段需要哪个流 | 计算量较大 |
| 可解释（看 routing weights 知道模型在看什么） | 训练较复杂 |
| 支持 prefix KV cache | 需要更多调参 |
| 单独训练每个流的"专用通道" | |

```python
class MultiStreamMoT(nn.Module):
    def __init__(self, num_layers=18, d_model=1024, ...):
        # 四个独立 encoder
        self.theia = ...
        self.vjepa = ...  # frozen
        self.point_v3 = ...
        self.lang_tokenizer = ...  # from PaliGemma
        
        # 各自的投影到统一维度
        self.proj_img = nn.Linear(theia_dim, d_model)
        self.proj_dyn = nn.Linear(vjepa_dim, d_model)
        self.proj_3d = nn.Linear(point_dim, d_model)
        # lang 不需要投影（PaliGemma 已经是 d_model）
        
        # Type embeddings
        self.type_emb = nn.Embedding(4, d_model)
        
        # World-side Gemma (类似 PaliGemma)
        self.world_gemma = GemmaModel(config_world)
        
        # Action-side Gemma (类似 π0.5 的 expert)
        self.action_gemma = GemmaModel(config_action)
        # 关键：head_dim 对齐，让 joint attention 可以拼接 K/V
    
    def forward(self, rgb, rgb_seq, point_cloud, text, noisy_action, time):
        # 并行计算四个流
        img_tokens = self.proj_img(self.theia(rgb)) + self.type_emb(0)
        dyn_tokens = self.proj_dyn(self.vjepa(rgb_seq)) + self.type_emb(1)
        td_tokens = self.proj_3d(self.point_v3(point_cloud)) + self.type_emb(2)
        lang_tokens = self.lang_tokenizer(text) + self.type_emb(3)
        
        # 拼接成 world tokens
        world_tokens = torch.cat([img_tokens, dyn_tokens, td_tokens, lang_tokens], dim=1)
        
        # action embedding (类似 π0.5)
        action_emb = self.action_in_proj(noisy_action) + time_emb
        
        # Joint attention with prefix-LM mask
        mask = make_prefix_lm_mask(world_tokens.shape[1], action_emb.shape[1])
        
        # MoT forward（每层做 joint attention）
        action_out = self.mot_forward(world_tokens, action_emb, mask, time_emb)
        
        v_t = self.action_out_proj(action_out)
        return v_t
```

## 五、关于"joint attention 怎么学习跨流"的深入解释

你问到了核心：**为什么 joint attention 能学到"该看哪个流"？**

### 学习机制 1：Type Embedding 提供"流的身份"

每个 token 加 `type_emb` 后，attention score 里**自动包含了"我是谁、对方是谁"**：

$$
\text{score}_{ij} = (q_i + e_{\text{type}(i)}) \cdot (k_j + e_{\text{type}(j)})^\top \\
= q_i k_j^\top + q_i e_{\text{type}(j)}^\top + e_{\text{type}(i)} k_j^\top + e_{\text{type}(i)} e_{\text{type}(j)}^\top
$$

后面三项让模型可以学到"action 该多看 3D token、少看 dynamics token"这种 type-pair 偏好。

### 学习机制 2：Loss Backprop 自然引导

训练时：
- **如果一个任务需要精确空间**（如插入孔）→ 通过 `3d_tokens` 才能拿到精确位姿 → 反向传播让 action 的 attention weight 偏向 3d token
- **如果一个任务需要长程规划**（如多步操作）→ 通过 `lang_tokens` 拿到 subtask → attention 偏向 lang
- **如果一个任务需要物理直觉**（如抛接）→ 通过 `dyn_tokens` 拿到运动信息 → attention 偏向 dynamics

**这种"流偏好"是模型在数据上自动学到的，无需显式监督**。

### 学习机制 3：Type-Pair 的归纳偏置

可以引入显式的**type-pair attention bias**强化这种学习：

$$
\text{score}_{ij}^{\text{biased}} = q_i k_j^\top + b_{\text{type}(i), \text{type}(j)}
$$

其中 $b \in \mathbb{R}^{4 \times 4}$ 是可学习的 type-pair bias，让模型快速学到哪些流对常常重要。

### 学习机制 4：Auxiliary Loss 加速学习

可以加辅助任务：
- **跨流 contrastive loss**：让同一时刻 image 和 3d token 在 latent 空间对齐
- **Stream prediction loss**：random mask 一个流的 token，让其他流预测它（类似 masked modeling）

这些 aux loss 让模型**显式学到流之间的对应关系**，而不只是隐式从 action loss 反向传播。

## 七、关键设计决策总结

| 问题 | 答案 |
|------|------|
| 四个 encoder 之间有依赖吗？ | **没有**，完全并行独立 |
| 跨流融合发生在哪？ | **MoT 的每一层 joint attention 内部** |
| 谁做 Q，谁做 K/V？ | **每个 token 既做 Q 又做 K/V**（标准 self-attention），但跨 type 时通过 type embedding + type-pair bias 学习偏好 |
| 跨流学习靠什么？ | ① Type embedding ② Type-pair bias ③ Action loss 反向传播 ④ Auxiliary contrastive/masking loss |
| 单向还是双向？ | **Prefix-LM**：world 块内部双向，action → world 可见，world → action 禁止（保 KV cache） |
| 计算量怎么控制？ | World 块 KV cache 一次算好；action 块只算 16 个 token 的迭代 |

## 八、一句话总结

> **四个流是"并行独立采集 + 统一 type embedding 投影 + Prefix-LM Joint Attention 融合"的三段式架构。跨流学习不需要任何显式的 Q/K/V 分配规则——只要给每个 token 加上 type embedding 进入同一个 attention，模型就会通过 action loss 反向传播自动学到 "该看哪个流"。**
>
> **关键不是"谁做 Q 谁做 K/V"，而是"如何用 type embedding + prefix-LM mask 把信息流向控制好"——这是 π0.5 MoT 设计真正的精髓，也是它能扩展到任意多流的关键。**

如果你要做具体实现，**先按方案 B（prefix-LM joint attention）跑通 baseline**，然后再考虑升级到方案 D（stream-routed MoE）。前者基本是 π0.5 代码的"多流扩展版"，工程上一两个月可以完成。
