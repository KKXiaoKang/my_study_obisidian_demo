## 参考主流具身 / 仿真 benchmark 的常见分层（与你可对齐的「名字」）

不同项目命名不同，但骨架高度相似：

1. Robot / Asset：只描述刚体、关节、执行器、默认初始位姿（你已有 `kuavo_cfg.py`，可再拆 `kuavo_assets/`：USD 路径解析、版本、eef 变体）。
2. Scene template：灯、地面、静态装饰、可复用的物体 prefab（无 ROS、无主循环）。
3. Task / Episode：本局目标、成功/失败、reset 采样分布、随机化范围（LIBERO / Meta-World / RLBench 的「task」层）。
4. Observation / Action adapter：从 `InteractiveScene` 读张量，转成 policy 或 ROS 消息（对应 benchmark 的 `obs`/`action` 空间定义）。
5. Runtime / Driver：仿真步进、与外部控制器同步（你现在的 `run_simulator` + 500Hz `rospy.Rate`）。
6. App entry：只负责 `AppLauncher`、解析 CLI、选配置文件、调 `main()`。

Isaac Lab 生态里更接近这一套的是：`ManagerBasedRLEnvCfg` 一类把 _scene / observations / commands / events / terminations_ 拆开；即便你不做 RL，也可以只借用「配置类 + manager 思想」，用 ROS 替换 RL 的 action 来源。
