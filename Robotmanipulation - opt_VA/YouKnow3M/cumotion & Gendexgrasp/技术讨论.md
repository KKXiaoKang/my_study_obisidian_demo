### 一、 cuRobo 算法构造与 GPU 并行优化原理

在 `cumotion_planner.py` 中，核心调用了 `curobo.wrap.reacher.motion_gen.MotionGen`。与传统基于 CPU 的 RRT/OMPL 或纯数学规划器不同，cuRobo 的核心思想是**万物皆 Tensor (Tensorized Robotics)**。

#### 1. 算法构造原理：轨迹优化的重构
cuRobo 的避障轨迹生成本质上是一个**基于梯度的非线性优化问题 (Non-linear Trajectory Optimization)**，但它的前置步骤不是你提到的线性插值，而是：
*   **多种子点生成 (Multi-Seed Generation)：** cuRobo 首先在关节空间生成数千条初始轨迹（种子）。这些种子可能来自于关节空间的直接插值、也可能来自于并行的图搜索（如 GPU-PRM）产生的无碰撞粗糙路径。
*   **代价函数 (Cost Function)：** 算法将问题转化为最小化一个复合代价函数：
    $J = W_{goal} \cdot C_{goal} + W_{collision} \cdot C_{collision} + W_{smooth} \cdot C_{smooth}$
    *   $C_{goal}$：正运动学 (FK) 算出的末端位姿与目标的误差。
    *   $C_{collision}$：机器人碰撞球与环境障碍物的穿透深度。
    *   $C_{smooth}$：轨迹点之间的一阶/二阶差分（速度、加速度限制）。

#### 2. GPU 并行优化方式 (如何榨干 GPU 算力)
*   **碰撞检测的降维打击 (Sphere vs ESDF)：** 在 `cumotion_planner.py` 的 398 行 `self.__world_collision.update_voxel_data(esdf_grid)`，nvblox 传入了 ESDF（欧式符号距离场）。cuRobo 将机器人的 URDF 转换成了一组重叠的**球体 (Spheres)**。在 GPU 上，计算几万个球体在一个 3D 距离场张量中的坐标插值，只需要一次简单的 CUDA Kernel 调用。
*   **L-BFGS / 拟牛顿法并行化：** cuRobo 不像 OCS2 那样去解全局的 QP。它在 GPU 上使用 **L-BFGS (或 MPPI)** 等一阶/拟牛顿优化器。由于正运动学和碰撞雅可比矩阵都是通过 PyTorch/CUDA 高度优化的纯张量运算，GPU 可以**同时对几百上千条种子轨迹进行梯度下降**。
*   **逃离局部最优：** 并行优化的最大好处是“大力出奇迹”。千条轨迹同时优化，谁先收敛且无碰撞（Cost < Threshold），就直接把这条轨迹作为最终输出。

### 二、 cuRobo 与 OCS2 的本质区别

你总结的 OCS2 流程非常标准：**Anchor 线性插值 -> SQP (非线性 OCP 局部化) -> QP (qpOASES) -> (State, Input) -> WBC (二次映射解关节力)**。这是一种典型的 **Newton/SQP 类方法**。

对比当前的 cuRobo (cuMotion) 方式，两者的区别是**世界观的差异**：

| 维度 | OCS2 (MPC + WBC) | cuRobo (cuMotion) |
| :--- | :--- | :--- |
| **问题域** | **最优控制问题 (OCP - Optimal Control Problem)** | **运动学规划问题 (KMP - Kinematic Motion Planning)** |
| **核心约束** | 刚体动力学 (Dynamics)、接触力、摩擦锥、质心动量、平衡。 | 避障 (Collision-free)、关节限位、速度/加速度平滑。 |
| **插值/前置** | **位置线性/姿态 Slerp (Anchor)**，生成初值供 SQP 迭代。 | **GPU-PRM 或多端点插值**，生成几千条种子轨迹供并行优化。 |
| **求解器架构** | **CPU 串行**。基于解析/有限差分的雅可比矩阵构建局部 QP，用 qpOASES 求解 `δx, δu`。 | **GPU 并行**。基于 L-BFGS 或 MPPI 进行张量梯度下降，同时优化成百上千条轨迹。 |
| **环境碰撞感知** | 极弱。通常只能处理自碰撞或简单的几何约束（放入 QP 不等式约束），遇到复杂点云/体素易导致雅可比不连续，SQP 发散。 | **极强**。直接对接 nvblox 的 Dense ESDF 距离场，非凸障碍物避障是其强项。 |
| **输出目标** | 状态 $x$ 与 控制输入 $u$ (最终推导为关节力矩 $\tau$)，通常运行在 **100Hz+ 闭环控制**。 | 离散的无碰撞关节轨迹点 (Joint Positions/Velocities)，通常用于 **低频全局/局部规划**。 |

**总结一句话：** OCS2 解决的是“**怎么站得稳、怎么用力**”（力控与平衡），cuRobo 解决的是“**在复杂的满是障碍物的空间里，怎么扭曲身体绕过去**”（几何与避障）。在你们的系统里，cuRobo 规划出安全的关节轨迹，最终其实需要交给类似 OCS2/WBC 的底层控制器去执行（追踪这条轨迹）。
